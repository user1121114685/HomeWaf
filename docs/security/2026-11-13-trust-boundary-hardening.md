# 2026-11-13 请求信任边界加固

本次修改由用户提供的 123 条真实安全事件驱动。测试使用脱敏重建的 HTTP 请求；没有连接或探测用户运行中的 WAF，也没有修改线上配置。

## 已修复的边界

1. **真实 IP 来源**：旧引擎的空模式只继承全局头名，不再隐式信任来访者。`header`、`xff_depth` 必须有明确的可信代理来源；来源不匹配、配置缺失或未知模式使用网络层地址。网卡模式始终忽略转发头。保存配置时拒绝整个互联网的 `/0` 信任段，运行时同样不采信旧 `/0` 配置。
2. **代理链解析**：合并重复 XFF 字段，从右侧跨过可信代理，取首个非可信地址。任何非法节点、空节点、超长链使整条链失效，不能通过丢弃右侧垃圾而选择左侧伪造值。普通单地址头拒绝多值。可信 CDN 的自定义 XFF 也按相同边界处理。
3. **后端身份一致性**：新旧引擎清除常见 IP 别名、供应商头和 URL/Host 重写头，重新生成 XFF、X-Real-IP、转发协议/Host/端口。处理发生在逐跳头清理之后，客户端无法通过 `Connection` 删除安全头。旧引擎按每次请求的已验证身份传递上下文，覆盖普通代理、路径代理与复用的负载代理。原始入站头保留给日志，不用清洗后的副本冒充原始证据。
4. **未匹配 Host**：来源日志始终使用网络对端；非法 XFF 不再使该请求在返回 403 后丢失日志。默认页面不再展示输入 Host、产品名称或接入步骤。自定义模板仍由管理员控制，因此不声称消除了所有响应差异。
5. **协议升级**：不支持的 Upgrade（包括 h2c）在回源前拒绝并记录。WebSocket 保留原有处理和认证路径。本次没有为健康检查、通知、分享或登录路径新增任何免认证规则。
6. **自动证书**：删除旧 Access 入口针对整个 ACME 目录的隐式认证豁免。只允许精确的 GET/HEAD 挑战请求在当前站点的本地挑战命中后由 WAF 自答。查询串、编码路径、额外目录、尾斜杠和 Upgrade 请求不能使用该快速通道；未知 token 进入正常防护与认证。新旧证书入口共用严格解析。响应兜底不再接管非法挑战路径；磁盘内容过大时拒绝，避免截断后当成有效挑战。

## 升级前确认

- 直连部署使用网卡模式。使用 CDN/反代时，先填写实际的代理出口 CIDR，或选用并校验 CDN 回源段。**原来靠“取最左”或不校验来源工作的配置，升级后会回退到代理节点 IP。** 这会影响日志、地域限制、限速、白名单和封禁归属，应在维护窗口核对。
- 代理应覆盖自己的单地址头，或正确追加 XFF；不能原样把客户端任意单地址声明当成权威值。受保护业务也应只信任 WAF 生成的规范身份头，并限制源站直连。
- 回源保留的规范身份头是 XFF/X-Real-IP 等。依赖原始 CF-Connecting-IP、True-Client-IP 或自定义覆盖这些身份头的后端，需要改为使用 WAF 输出的规范头。任意业务 Authorization/Cookie 不因本次身份清洗而删除。
- WAF 自己管理的有效 HTTP-01 挑战继续支持本地应答。后端独立运行 certbot、以前依赖 ACME 目录自动免认证的部署，需显式设计仅提供挑战文件的隔离路径，或使用 DNS-01；不要把整个目录作为通用业务旁路。
- 旧自定义拒绝页不强制覆盖。若曾复制默认“网站尚未接入”页面保存到数据库，需要管理员自行检查其对外信息。
- 地域限制用于减少暴露，不等于用户身份认证。获得允许地区的真实出口仍可能满足地域条件，敏感业务应保留独立认证。
