# 配置持续编辑检查

这次检查关注已有配置能否反复进入、修改、校验和保存，不要求用户在创建向导
中一次完成全部设置。检查保留现有页面和权限体系，不修改运行实例的业务数据。

## 修复内容

- 服务卡片、表格和常用设置增加蜜罐入口。蜜罐成为常驻页签，不再依赖展开
  高级配置。监听中的服务也可以进入修改，保存保留原服务和监听状态。
- 蜜罐提示改为逐条添加、修改标题、内容和权重、移除的表单。校验失败阻止
  保存；服务端保存失败保留当前草稿；取消不写入已保存配置。
- 通用字段编辑器按当前草稿对象保留未完成的 JSON 和多行文本。关闭重开
  高级面板后，不丢失输入，不再出现输入已消失但保存仍被旧错误禁用的状态。
- 共用同一个策略对象的多个表单只汇报各自字段的错误。替换完整草稿或重新
  打开服务时使用新草稿，旧会话的错误不会污染其他服务或新策略。
- 保存区显示未完成配置的定位入口。常用设置补充自动处罚入口；高级开关
  不再无条件跳离常驻的蜜罐页签。

## 检查范围

`web/scripts/audit-config-editability.mjs` 检查 45 个配置页面及其子组件的
编辑、提交、保存或更新入口，包括服务策略、IP 名单及分组、账号、规则、
证书、代理、应用、任务、通知、系统设置等。AI 模型管理、主机防护和 OWASP
的设置分别由模型操作或子组件承载，已沿组件继续检查。

这是入口与更新调用的结构性检查，不能等同于已向所有页面的真实后台各写入
一次。旧站点源记录对尚未接管的端口生效；已接管端口继续从服务配置编辑。
内置模板只读但可以另存为用户模板。账号标识、状态显示、密钥不回显等有意的
只读边界不因本次检查取消。

浏览器回归覆盖以下真实前端流程，管理 API 全部替换为隔离的内存响应，不向
开发实例的后台发送写请求：

1. 正在监听的服务直接进入蜜罐设置并保存，不重新创建或停止服务。
2. 刷新重开后继续修改提示、权重、阈值；新增、删除、校验及失败后重试。
3. 常用设置跳转蜜罐；取消草稿不改变已保存内容。
4. 服务名称和上游地址重复修改、保存、重开。
5. 代理 JSON 校验失败后关闭、重开高级面板，恢复输入、定位、修正并保存。
6. 登录门标题和已有访问账号分别修改保存。
7. 攻击规则与 IP 条目重复修改，保留其他策略分区。
8. 卡片与表格入口一致，修改一个服务不影响另一个服务。
9. 用户模板重命名、校验、保存、刷新后重开；桌面和手机布局不横向溢出。

真实 SQLite 回归还会连续三次修改同一端口的蜜罐、规则、登录门、网络和
IP 策略，每次从数据库重新加载，检查配置版本、内容和端口密钥；同时检查
过期编辑版本不能覆盖新配置。
