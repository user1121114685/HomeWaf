# 按端口的异常访问处置

入口：**接入服务 → 异常处置**，保存后可从 **我的服务 → 异常访问处置** 继续调整。服务仍使用原生 `pipeline/ports/save` 保存；操作人须具有安全管理员权限。每个监听端口有一个处置模式，同端口的所有域名/路由共用，其他端口和管理监听不受该状态影响。

## 模式与触发

接入新服务时必须明确选择并配置一种处置方式，四选一，不逐级升级。复制服务也需要选择；没有选择时不能继续，服务端也拒绝缺失或关闭处置的新建请求。保存仍不启动监听，启用服务后规则才会作用于访问。已有服务可在编辑页暂停处置。

| 模式 | 行为 |
| --- | --- |
| 无提示拒绝 `quiet` | 达到阈值后，对实际安全拒绝/认证失败停止发送提示，按所选 TCP 方式中止连接；通过检测的新来源和正常登录入口仍可使用。 |
| 收紧 IP `restrict` | 达到阈值后，冻结最近 30 天正常业务成功来源对应的 IPv4 `/16`、IPv6 `/64` 网段。网段仅是额外准入条件，不是免检授权。没有有效历史时关闭业务访问。 |
| 自动关闭 `close` | 达到阈值后设置现有 `policy.access.enabled=false`，包括 trusted 在内的业务访问均关闭，已有连接沿用排空设置。 |
| 蜜罐 `honeypot` | 第一次安全拒绝即可进入实例统一蜜罐，不等待计数阈值；正常访问不导流。 |

前三种默认 **30 分钟累计 10 次，持续 3 小时**，可按端口调整。计数跨来源 IP、按请求去重，不按不同 IP 数计数。正常请求不会清零。纳入安全策略拒绝、实际登录/令牌验证失败和登录入口的安全校验拒绝；不把普通业务 404/500、回源故障、正常登录挑战、观察信号及处置自身造成的拒绝当作新失败。

界面将参数解释为“在最近多长时间内”“累计多少次异常后处置”“处置后多久自动恢复”，并实时显示完整规则。例如：最近 30 分钟内累计 10 次安全拒绝或认证失败后关闭整个服务访问，3 小时后解除。本次期限从触发时开始；蜜罐不使用这三个触发参数，因此不显示。接入最终确认页重复呈现实际所选规则。

请求处理只修改有界内存，后台约每秒处理待提交状态；只保证状态提交后的新请求使用新处置，不追溯已开始的请求。持续期间的拒绝不会延长本轮期限。解除后重新计数。

## 恢复、编辑与重启

`defense_state` 与端口配置一同持久化，包含事件 ID、模式、原因、开始/结束时间、冻结范围及关闭前的访问状态。客户端不能通过保存端口配置伪造或覆盖它。

- **提前恢复**：携带配置版本和事件 ID，解除本轮限制；自动关闭时恢复此前允许的业务访问。
- **保持关闭**：即使访问开关已是关闭，也明确转交给管理员并取消定时恢复，旧定时任务不会再打开服务。
- **普通配置编辑**：不会覆盖自动状态。修改阈值或时长不改变本轮结束时间；自动关闭期间切换模式也保留原恢复任务，新模式在恢复后使用。停止监听或显式操作访问开关可结束自动管理。
- **进程重启/交接**：已触发的状态按原结束时间恢复；过期自动关闭须成功提交恢复后才放行业务。自动写入和历史持久化使用实例运行权校验，旧进程不得覆盖接任进程。
- **失败**：保存或恢复失败显示原因并重试，保留草稿；读取失败不转换成“没有记录”。成功来源不可用时不触发自动收紧，其他已有防护继续工作。

窗口计数在内存中，工作进程重启后重新累计；已触发状态不依赖窗口计数。成功网段约每 2 秒批量落盘，异常掉电可能损失尚未保存的增量。

## 成功来源

学习正常业务的 2xx/3xx 和成功 WebSocket 升级；排除登录门自身页面、蜜罐、证书挑战、失败响应和检测命中请求。普通业务成功不等于身份认证。来源使用现有可信代理解析，未配置的转发头不能伪造来源。

业务应用用 HTTP 200 表示登录失败时，须配置已有的业务登录成功判定规则，才能识别该失败并排除学习；不会自动猜测各应用的登录协议。HTTP/TLS 解析器的观察性诊断不作为此计数的安全拒绝信号。

存储网络前缀和最近成功时间，不存密码、会话或请求正文。每端口最多 4096 个网段、实例最多 32768 个；容量不足会阻止自动收紧并报告原因，不静默截断成不完整的放行范围。历史过期、存储失败和正常空历史是不同状态。删除服务同时清理其摘要，旧请求不能把旧服务的来源带入同端口新建的服务。

## TCP 动作的真实边界

- **立即断开/复位**：在受管 TCP 连接上关闭连接，不返回拒绝正文。HTTP/2 同一连接上的其他流也会随连接结束。明确的 IP 级拒绝可在连接接收入口执行；依赖 URL/凭据/内容的判断必须收到请求后才执行。
- **静默丢包**：当前实现要求 Linux 的 `iptables`，双栈/IPv6 还要求 `ip6tables`，且具备正确网络命名空间中的防火墙操作权限。规则只匹配被拒绝连接的本地/远端地址及端口，双向 DROP，不调用整机 IP 封禁接口。接受 TCP 连接并不表示已在 SYN 之前识别请求。
- 连接 DROP 规则使用 **2 分钟的回收期限**，与端口处置持续 3 小时是两个不同期限；后台每 30 秒清理带本模块命名标记的过期规则。规则期限写入注释，重启后继续清理。实例最多保留 512 个在途连接租约、8 个防火墙执行槽，命令有超时。执行失败/资源不足会中止连接并报告实际运行错误，不声称内核丢包成功。
- Windows/macOS 当前不提供本模块连接级静默丢包，界面禁用该选项并说明原因；立即断开仍可用。
- 配置了前置可信代理的服务不能启用该 TCP 处置模式，避免终止可能由多个访客复用的代理连接；应使用其他模式。不会把代理 IP 当真实攻击者做整机封禁。

连接入口的拒绝不产生新的 HTTP 请求日志，可查看 `global_defense_connection_rejections` 计数；已进入请求流程的处置保留规则、原因及 trace。可选通知沿用现有通知队列，是否送达取决于用户的渠道配置。

## 统一蜜罐与配置

入口：**防护策略 → 统一蜜罐**（`/waf-pipeline/honeypot`）。全实例一套内容、权重、运行限制和归档，服务仅选择蜜罐模式。页面展示使用中的服务、旧配置候选及可按服务筛选的最近 20 条记录。

不再要求迁移确认。管理员直接选择并保存处置方式；保存后旧蜜罐阈值和多来源锁定不再并行执行，单来源自动封禁限定本端口。已有 IP 封禁记录按原有效期处理。加载旧开发配置的兼容逻辑保留；原端口蜜罐字段只读，不能成为第二条内容写入路径，旧模板也不能重新启用这些退役控制。首次使用蜜罐需先在统一页面保存内容，接入页提供就绪检查、失败重试和新标签页返回。

普通表单无需编辑 JSON。打开统一蜜罐的配置捷径使用新标签页，让原服务草稿留在原处；放弃修改、即时恢复和影响多个服务的保存都有明确确认。

首次配置可以保留内置页面，或选择“管理入口、设备管理、文件管理、应用运维”四种文字模板。模板只填写一页的标题和说明，保留其标识、分配份数和其他设置；替换已有文案会先确认。多页的权重以“分配份数”和估算来源比例解释，一页时无需调整。归档、诱饵路径和运行限制均有用途、默认值与影响说明。

“对方会看到什么？”支持首次访问、提交登录后的固定失败提示，以及并发满时的 503 繁忙响应。预览跟随草稿，使用只读隔离页面，不输入真实口令、不发送业务请求、不保存或启用配置。保存后仍须在服务中选择蜜罐模式并启动监听，实际效果通过业务访问和记录确认。模板与预览的验收范围见 [蜜罐易用性评审](../modernization/HONEYPOT-USABILITY-REVIEW.md)。

## 接口与验证

新增接口均在现有认证/加密封装和安全管理员角色检查之下：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/pipeline/defense?port=...` | 当前计数、历史可用性、状态、错误和版本 |
| `GET /api/v1/pipeline/defense/capabilities?ip_version=...` | 实际 TCP 能力与执行错误 |
| `POST /api/v1/pipeline/ports/access` | `{port, revision, state_id, action}`；`action` 为 `open`、`close`、`release` |
| `GET /api/v1/pipeline/honeypot` | 统一配置、旧候选、使用服务与记录筛选来源 |
| `POST /api/v1/pipeline/honeypot/save` | 版本化保存统一配置 |
| `GET /api/v1/pipeline/honeypot/logs?port=0` | 最近 20 条；0 为全部端口，可指定端口 |

新建端口必须提交已启用的 `policy.defense`，字段为 `enabled`、`mode`、`window_seconds`、`count`、`duration_seconds`、`tcp_action`。模式、数值范围及运行先决条件由服务端校验；不存在迁移确认字段。读取旧存储配置时仍允许没有 `policy.defense`。

回归覆盖在 `wafpipeline/defense_test.go`、`service/waf_service/waf_pipeline_defense_test.go`、`firewall/flow_drop_test.go`；前端完整操作与三尺寸/两主题验证为 `node web/scripts/verify-defense-browser.mjs`，默认连接隔离的 Vite 前端 `127.0.0.1:3081`，所有管理 API 被测试夹具拦截。结果与截图位于忽略目录 `artifacts/port-defense/`。

真实本地 TCP/HTTP 测试覆盖拒绝、正常登录、业务认证响应不泄露，以及持久化关闭到真实监听再恢复。防火墙命令测试使用夹具，不修改本机防火墙；这些结果不能替代 Linux 实机双栈内核 DROP 抓包验收，也不证明外部通知送达。
