# 开源部署的安全边界

HomeWaf 按源码和算法完全公开设计。保密性来自实例自己的随机密钥，官方授权的真实性来自发行方的 Ed25519 签名私钥；不依赖隐藏源码、混淆、反调试或全实例共用的内置秘密。所有新增保护保持 `CGO_ENABLED=0` 可构建。

## 标准 SQLite 与敏感字段

SQLite 文件结构、表名、普通配置和日志仍可由标准工具读取。以下字段通过 GORM 自动使用 AES-256-GCM 加密，`hwf1:` 密文同时认证表名和列名：

- 网站 TLS 私钥、证书夹私钥、证书申请私钥及结果私钥。
- DNS / 云厂商凭证仓库中的 `private_value`。
- 通知渠道的签名秘密、AccessToken、Webhook URL 和配置 JSON。
- 网站 HTTP 认证密码（现有编辑与校验流程仍需要可恢复的值）。

创建、保存及正常 map 更新均覆盖；密钥不可用时拒绝写入，错误格式、篡改、错误密钥和跨表/列搬运的密文读取失败，不回退到明文。原有 Access/CDN/2FA/敏感系统配置继续使用每实例 AES-GCM；2FA 和系统配置加密失败不再落明文。运行期不接受公开旧通讯密钥生成的 CBC 数据，也不自动把数据库内的明文或旧密文转换为可信秘密。

普通开放平台 API Key 仅首次创建/重置返回明文，数据库保存实例密钥保护的 HMAC-SHA-256 摘要；摘要不能作为 API Key 使用。CLI 本机 Key 因需要再次显示，仍加密保存。登录密码继续采用 bcrypt。SQL 日志保留参数占位符，不展开绑定值。

这些措施不是整个数据库的防篡改系统。表内其他配置、日志、会话记录没有因此全部加密或签名；同一字段旧密文的重放也没有被阻止。不要把数据库写权限授予不可信用户。通过 `Raw`/`Exec`、跳过 GORM hooks 或直接修改 SQL 文件的维护代码不得用作正常秘密写入通道。管理员主动导出的证书私钥、Excel、日志文件可能含明文，应按秘密文件保护。

## 实例密钥与备份

新安装的默认数据密钥是安装目录下 `.homewaf-keys/data_key`，与 `data/` 数据库分离。也可在 `conf/config.yml` 设置 `security.data_key_file` 指向运维预先配置的独立文件。自管文件为 base64 编码的 32 个安全随机字节，必须持久化且单独备份；不得使用示例值、口令或发行方授权签名私钥。

- Unix 使用 0600，拒绝组或其他用户可访问的密钥文件。
- Windows 新文件显式设置仅服务账号及 SYSTEM 可访问的 DACL；读取时拒绝向其他普通主体开放的文件，允许系统管理员权限。0600 本身不能约束 Windows ACL。
- 密钥以完整临时文件加独占硬链接发布，多个 Worker 并发初始化使用同一把密钥，不覆盖已有密钥。底层文件系统必须支持硬链接。
- 拒绝密钥符号链接、非法内容及过大的文件。已有本地数据库却找不到默认密钥时停止初始化；自管密钥不存在时也报错。
- 旧 `data/.keys/data_key` 不自动覆盖或重新生成。开发阶段如需保留其余已加密数据，应显式移动原文件或配置原路径。此次新增字段不提供历史明文自动迁移，请按项目当前无存量用户的部署约定使用新数据目录。

Docker 增加 `/app/.homewaf-keys` 持久化卷，部署时为它指定独立持久卷或密钥挂载。只备份 `data/` 不含数据密钥；恢复时必须恢复对应的密钥，不能生成替代品。远程 MySQL/PostgreSQL 同样依赖本实例密钥，操作员必须防止删除后以新密钥重建实例。`rekey` 是显式旧字段格式转换工具，不是密钥轮换或新增字段迁移工具；`rekey-legacy` 入口已停用。

拿到数据库和正确密钥的人仍能解密。若攻击者能读取整个安装目录、获得服务账号权限、读取进程内存或控制 root/Administrator，本地加密不构成防线。重要部署应使用独立服务账号、目录权限、独立密钥备份；更高要求可在后续对接运维的密钥管理服务。

## 官方授权与开源修改

官方构建只信任编译时配置的 Ed25519 公钥。签名私钥仅保存在发行方离线签发环境，不能提交到仓库或放进发行包。未配置公钥的构建不接受商业授权。

授权判断每次重新读取有大小限制的普通授权文件并验签，核对产品、实例、有效期和功能。修改/删除授权文件、改写数据库或 UI 中的会员状态，都不能让未修改的官方程序获得未签发功能。实例 ID 现在包含数据密钥派生的公开标识：仅复制数据库、配置和授权文件不能克隆实例。它不是硬件锁；同时复制实例密钥仍可能克隆，离线系统也没有可信时间服务来彻底阻止系统时钟回拨。

现有基础功能没有新增付费限制。`RequireEntitlement` 是未来明确商业功能可使用的后端入口；产品的付费范围尚未定义，不能把存在验签模块说成已经完整实现了收费控制。

源码公开且在用户机器上执行的功能，无法阻止用户删掉授权判断后重新编译。签名保证官方程序只接受发行方签发的授权，不保证用户无法修改程序。若未来商业服务需要不可由客户端绕过的计费，应由实际提供该服务的服务端验签并执行权限/配额控制；本次没有新增远程认证、遥测或强制联网。
