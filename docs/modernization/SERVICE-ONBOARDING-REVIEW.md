# 首次接入与异常访问处置

## 产品合同（2026-11-16）

用户明确要求接入时必须配置异常访问处置、移除迁移确认，并让第一次使用的人理解每个选项及其联动。入口为工作台/我的服务的“接入服务”，对象为一个新监听端口；复制草稿也需完成同一流程。

流程：选择服务场景 → 填原服务地址及可选访问限制 → 必选异常处置方式 → 检查端口、连接与策略 → 确认完整规则并保存 → 待启用服务。正常访客、被拒绝访客、整个服务三种影响范围须清楚区分。保存不等于监听或业务可达。

处置选择展示四种方式及各自后果。累计范围、异常次数、自动恢复时间用问题解释，并组合为与草稿同步的一句完整规则。蜜罐第一次安全拒绝就生效，因此不展示累计和恢复参数。收紧 IP 说明首次使用无成功记录时会关闭业务；TCP 处置说明前置代理限制；蜜罐未就绪时提供新标签页设置、返回及重新检查。

访问账号与管理账号不同，且不代替原业务登录；API 场景需生成令牌后再启用；地区和 IP 组匹配任意一项即可通过来源白名单，黑名单优先，放行来源仍执行认证与检测；HTTPS 需证书与配套私钥。上述约束在任务中出现，不靠隐藏的高级设置或成功提示补救。

启用服务时选择“先观察运行”会暂停异常处置，现已在启用说明中明确。该选项保留原行为；默认“按当前策略启用”使用刚保存的处置方式。

验收：未选择处置方式不能继续；缺失/关闭处置的新服务不能通过保存接口创建；四种方式保存到同一原生端口记录并由原运行时消费；返回修改和请求失败保留草稿；保存后重开能继续编辑；取消不会提交草稿；没有迁移勾选或确认字段。现有即时恢复、保持关闭、版本冲突与自动恢复语义保留。
