# 证书生命周期实施记录

日期：2026-11-17。依据：[已确认的产品与交互方案](SSL-MANAGEMENT-REPLAN.md)。实现覆盖证书、申请任务、失败恢复、共享凭据、服务绑定与外部监测；没有修改用户运行实例的配置，也没有向真实 CA、DNS 或通知渠道发送请求。

## 持久化与运行链路

- `SslConfig` 仍是证书资源；新增 `SslRenewalPolicy` 持有长期策略、版本、稳定服务 ID、材料指纹、最近任务和重试时间。必要 ACME 上下文使用现有秘密序列化器加密保存，不再依赖可删除的历史记录。
- 迁移只采用精确材料匹配、真实服务绑定和对应最新成功来源。配置冲突显示“来源待确认”，用户核对选择后保存；不以域名字符串猜测绑定。文件接管、手动替换、解绑/重建后的旧任务受来源与指纹检查保护。
- 证书续期请求只提交证书 ID 和幂等请求 ID，服务器读取当前策略；活动任务返回同一任务。旧订单接口适配到同一服务层，正常计划任务和重试维护循环共用策略源。
- 任务区分签发、入库/部署、导出；保留签发材料、原始绑定快照和逐绑定结果。已保存签发材料的恢复不会再请求 CA。原生端口通过版本化保存和 TLS 更新消费者，旧站点通过原绑定路径；HTTP 服务绑定证书不等于启用 HTTPS。
- 证书删除检查服务、控制台和活动任务；历史删除保护尚未迁移/确认的来源与恢复材料。普通新列表/详情不返回私钥；兼容的旧 `sslconfig` 接口保留已有编辑调用者语义，未宣称本次改造全局消除了旧私钥读取接口。
- `SslExpire` 保存真实 `LastDetect` 与 `LastSuccess`，过期天数保留负号。单目标检查具有持久状态和超时恢复；超过 48 小时的旧结果标为陈旧，失败不会变成“正常”或空列表。

## 失败后的确定行为

| 情况 | 实际处理 |
| --- | --- |
| 暂时网络、DNS 传播等异常 | 失败后 15 分钟、1 小时、4 小时，后续每 6 小时；附加 0–60 秒稳定正向抖动 |
| 自动尝试预算 | 单张证书滚动 24 小时最多 6 次；等待下一窗口，不关闭用户的策略 |
| CA 限流 | 保存 `Retry-After`；自动和人工申请都受最早允许时间约束 |
| 配置错误、失效绑定、来源变化、结果未知或中断 | 暂停自动提交，保留明确错误和人工核对/恢复入口 |
| 已签发但部署/导出失败 | 恢复保存的签发材料，仅继续失败阶段；更新服务前再次核对身份、绑定和指纹 |
| 已过期托管证书 | 策略和条件有效时受控重新申请，仍遵守预算/限流；不会隐藏过期状态 |
| 关闭策略 | 不再产生自动尝试，取消尚未执行的自动任务；在途任务仍显示其真实执行状态 |

首次申请失败保留人工重试；自动续期从成功签发/预定绑定后的证书策略开始。保存续期设置、手动续期、服务部署、导出与外部探测是独立操作，不用单一成功提示代替所有结果。

## 通知与投递恢复

`CertificateEvent` 与任务结果一起持久化，`CertificateDelivery` 按订阅/渠道保存发送、重试与失败。故障走 `operation_notice`，到期风险走 `ssl_expire`；成功恢复有独立事件。保留用户已有过滤、级别、免打扰、冷却和聚合窗口，不自动修改订阅。

发送失败按 1 分钟、5 分钟、30 分钟、2 小时、6 小时退避，后续 6 小时；遵守渠道 `Retry-After`。超过 24 小时标记本轮投递失败，可人工重发；重发检查已有在途投递和限流，不触发证书签发。发送采用持久租约，不能承诺外部系统严格一次送达：远端已接收而本地进程在记账前中断时，恢复后可能重复投递。

证书与任务详情显示启用的操作/到期订阅覆盖、未订阅、禁用、过滤、等待、渠道已接收或失败；渠道接收不代表人已读。重复相同证书故障在 24 小时内合并事件，用户的订阅还可继续聚合/过滤。库内到期风险使用当前绑定版本的最早有效期，避免新材料已入库但服务仍使用旧证书时漏报。
