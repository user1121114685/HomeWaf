# 统一蜜罐模板与预览（2026-11-17）

## 产品合同

这是现有运维控制台的局部任务改进。用户明确要求内置模板、引导填写，并能预览蜜罐反馈。

- 用户：有安全管理员权限、首次配置蜜罐的家庭服务管理员。
- 对象：实例共享的仿真登录页面、记录选项和运行限制；服务是否选择蜜罐模式仍由各服务配置拥有。
- 入口：防护策略 → 统一蜜罐；服务处置配置的新标签页捷径携带原端口。
- 顺序：了解当前状态 → 选择内置模板 → 修改标题/说明 → 预览首次访问、提交登录和繁忙响应 → 保存共享设置 → 返回原服务或选择服务配置蜜罐 → 查看记录与验证说明。
- 主操作：保存统一蜜罐设置。选模板、编辑和预览只改变本地草稿，不启用服务、不发送业务请求。
- 恢复：模板替换已有文案须确认；取消不改草稿；保存失败保留输入；重新加载/离开保留放弃确认；日志错误有重试且不展示成功空态；返回服务不随日志筛选改变。
- 语义：内容已保存、服务已选择蜜罐、监听已运行和实际请求命中是不同事实。页面只能根据现有接口证明前两者；本地预览不作为上线验证。

## 能力去向与依据

| 既有能力 | 本次呈现 | 持久化与运行消费者 |
| --- | --- | --- |
| 默认页、自定义标题/内容、多提示权重 | 内置文字模板、可编辑表单、出现比例说明；保留每个提示 ID 和权重 | `honeypot/save` → 共享记录 → `HoneypotPolicy` / `selectHoneypotLure` |
| 初次访问与登录失败响应 | 隔离只读预览，按 `honeypot.go` 的实际布局和固定失败文案生成 | 预览不调用管理/业务接口；真正响应仍由原 Go handler 生成 |
| 并发满时 503 | 可选择的繁忙反馈预览，显示真实状态码和 Retry-After 行为 | 原 admission 限额，无新增保护策略 |
| 脱敏归档、大小上限 | “额外保存提交内容”，开关与状态常驻，上限按需展开 | 原 `archive_body` / `archive_max_bytes`，不丢失隐藏字段 |
| 陷阱路径、并发、延迟 | 分开说明目的和风险；运行限制按需展开，摘要显示当前值 | 原共享字段，后端校验与运行消费保留 |
| 旧配置复用 | 保留选择、只读详情和导入草稿，降为次要入口 | 仍仅导入原六个共享字段，不恢复旧自动处罚 |
| 使用服务与日志 | 明确为“已选择蜜罐模式”；保留服务筛选、详情和最新 20 条 | `honeypot` 的 shared/legacy/services/sources 与 `honeypot/logs` |

## 验收标准与证据

- 初次使用可直接使用内置页，也可从模板生成可编辑内容；模板选择不覆盖其他页面或保护参数。
- 多条提示仍能增删改与调整比例；取消模板替换不丢文案。
- 预览跟随草稿，支持首次访问/登录失败/繁忙；不收集口令、不发送表单、不执行用户内容。
- 保存 → 离开 → 重开 → 再编辑；失败/冲突保留草稿，重复提交和取消有验证。
- 三尺寸、明暗主题、键盘、错误/空态检查；服务来源上下文不被日志筛选改变。
- 后端/API 静态审计基线为 605/462/6/137（注册/可达/客户端待复核/无静态引用）。权限仍为安全管理员，保存仍走认证加密客户端。
