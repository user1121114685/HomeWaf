# 对话框尺寸检查

日期：2026-11-16。用户在统一蜜罐页面反馈“未保存的修改”提示框过长，随后要求检查其他对话框并提交修复。

## 任务与验收

管理员编辑配置后尝试离开，提示框说明将丢弃草稿，并提供取消与确认；取消或按 Esc 返回原编辑状态，只有确认才离开。短提示应保持紧凑宽度，手机保留两侧边距；长文本应换行，按钮可见。配置表单、输入框、日志和预览保留其所需宽度、字段、校验与滚动方式。

## 原因与修复范围

| 对话框类型 | 检查发现 | 修改 |
| --- | --- | --- |
| `ElMessageBox` 提示/确认框 | 公共 CSS 将组件的 420px 上限覆盖成视口宽度；实际 1920px 窗口中的提示框宽 1888px | 同时保留组件宽度上限和视口边距限制；桌面与平板实测 420px，390px 手机实测 358px |
| `DialogPlugin` / `$dialog` 确认与提示 | 未传宽度时继承 `ElDialog` 的 50% 默认宽度，短提示随大屏放大 | 共享适配器默认上限 480px；显式传入的宽度继续优先，既有表单输入与回调保留 |
| 页面直接使用的 `ElDialog` / `hw-dialog` | 与上述提示框分属不同用途；已有具体表单、预览与日志尺寸 | 保留页面设置，验证其视口边界与操作流程，不给所有表单统一套用短提示宽度 |

静态检查覆盖 11 个直接使用 `ElMessageBox` 的文件、23 个使用对话框适配器的文件，以及 66 个含页面对话框的文件。以上是文件级调用清单，不代表逐个打开所有弹窗完成全量功能验收。原生 `ElMessageBox.prompt` 当前没有页面调用；输入内容由已有表单/适配器的渲染回调承担。

## 验证证据

- `verify-config-editing-browser.mjs`：真实蜜罐草稿离开流程，在 1920/820/390、明暗主题下测量提示框；取消与 Esc 保留输入且没有写请求，确认放弃后持久化内容不变。6 个提示框视图保存在 `artifacts/config-editability/`。
- `verify-secondary-console-browser.mjs`：在真实应用的隔离浏览器中调用现有共享适配器，验证确认、提示、长文本/连续标识符、带输入内容的自定义宽度四类弹窗；640px 自定义表单宽度保留。并复验应用编辑与恢复、隧道、HostGuard、OWASP、旧站点编辑等实际流程，共 78 个尺寸/主题视图。报告在 `artifacts/console-subpages/browser/report.json`。
- `verify-api-ui-integration-browser.mjs`：复验规则文件预览、高级基线、配置项维护、IP 条目、通知订阅、会话、CC 和规则辅助等二级流程；管理 API 使用隔离夹具。
- 前端类型检查、常规测试与生产构建通过。构建保留现有的大体积 chunk 提示。

检查包括截图查看、横向溢出、取消/确认、失败保留草稿、自定义表单宽度与输入。没有改动后端行为，也没有在用户的真实实例执行确认、删除或保存。浏览器夹具的结果不代表对真实外部服务的写操作验收。未使用营销页面的照片、全屏分节或动画 gate。
